# nfr-conflict

## Context
* [Workflow](../WORKFLOW.md) §4.6 - where this check is registered
* [Boundary Model](../../datamodel/boundary-model.md) §7.1 - several boundaries may apply rules to one function
* [Condition Model](../../datamodel/condition-model.md) §5 - a rule as a generator of required effects

## Purpose

Do two rules demand incompatible things of one function? A rule contributes required effects into the cells it
reaches, and a function may sit on more than one cross-cutting boundary — so two rules can arrive at one cell
requiring effects that cannot both hold.

## What It Inspects

For every cell reached by more than one rule, whether the required effects those rules contribute are mutually
satisfiable — two rules on the same design target requiring incompatible effects of the same function under the
same cell.

## Notes For P6

There is no local edit that resolves this: both effects are generated by rules, and a rule's content is
normally a Product-level statement rather than this design's to change. So the routes are a decision about which
rule should not govern this function — changing the selection, which *is* local — or a change request against
whoever owns the rule.

A cell off-nominal on two rules at once is **not** itself a conflict, and must not be reported as one. Where
neither deviation short-circuits the other — a rollback under a concurrent writer — the cell legitimately
belongs to both rules' views and both state it. Most such cells do not arise at all, because a deviation that
terminates or diverts the path collapses everything downstream of it.
